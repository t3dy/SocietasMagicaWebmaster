Societas Magica — Site Work Action Map

How to use this map

This is a breakdown of all the work needed to take over, stabilize, and improve the Societas Magica website. Each card below represents a distinct task. Click any card to expand and see details, technology options, effort estimates, and links to full implementation guides.

Tasks are organized by priority (fixing broken things first) and effort (quick wins before big projects). Cards are color-coded to show whether each task is Essential or Nice to Have.

1. Fixing Existing Functionality

The site has known broken pages and outdated content. These fixes must happen first — they're the foundation for everything else.

Restore Contact Page (404)
Essential Critical
▼

The problem: The contact page returns HTTP 404. Visitors, journalists, and prospective members cannot reach the organization. This is a basic credibility issue — a broken contact page signals that the organization is inactive.

What it looks like now: Anyone visiting /contact or /contact_us gets an error page instead of an officer directory with contact forms.

Why This Matters
Journalists, prospective members, and institutional partners all expect a working contact form and officer directory. A broken contact page is often the first thing visitors see if they search for "Societas Magica contact." It's a missed opportunity every time.

Immediate fix (1–2 hours)

Either restore the original URL (if it was just moved) or rebuild the page from the officer data in the database. The outgoing webmaster should know what happened.

Better long-term fix

See the "Officer Directory Self-Management" action below. Instead of maintaining contact info in files, store it in a form. The contact page renders from the database and is never a static file that can break.

⏱ 1–2 hours (quick fix) / 2–3 hours (database-backed long-term)

Stabilize PayPal/Payment Processing
Essential Critical
▼

The problem: PayPal IPN (Instant Payment Notification) recently broke. Members paid their dues successfully at PayPal, but their accounts never got activated on the website. This happened silently — nobody knew until members complained.

Why it's urgent: This is the #1 failure point for a membership organization. If payment doesn't activate membership, you lose both the member and the revenue.

How PayPal IPN Works
When someone pays, PayPal sends a webhook to a script on your server (e.g., /paypal/callback.php). That script checks the payment status, verifies it came from PayPal, and updates the member record in the database to active=1. If that script has an error, or if PayPal can't reach it, the payment succeeds but the member is never activated.

Immediate fix (2–4 hours)

Get SSH access to the server. Find the PayPal callback endpoint. Check the error logs to see what went wrong. Test it by making a small payment. You may just need to fix a database query or a mismatched credential.

Better long-term fix (1 day)

Replace PayPal IPN with Stripe Billing. Stripe's webhook system is more reliable, it handles subscription renewals automatically, and it has better error reporting. If migrating to WordPress/Outseta, this becomes automatic and you get renewal reminders for free.

⏱ 2–4 hours (diagnosis) + 1 day (Stripe migration, optional)

Update Content (Last changed 2012)
Essential
▼

The problem: Multiple pages show "Updated: January 12, 2012" — over 14 years ago. Membership benefits, publications, and officer bios are out of date or incomplete. This gives the false impression the organization is dormant.

Visible impact: Any visitor sees immediately outdated content. Search engines also notice stale updates and rank the site lower.

Pages needing urgent updates

  • Membership page — Verify dues amounts, journal subscription options, benefits list
  • Publications page — Add recent Magic in History titles and MRW issues
  • Conferences page — Add 2024–2026 session information
  • Home page — Update officer info, recent announcements

How to do it

Visit every public page. Check the date footer and content accuracy. Edit in place (if it's a static file) or update the database record (if it's data-driven). Add a current date to the footer when you finish.

Long-term solution

Content that's updated frequently (officer names, dues info, conference listings) should be stored in a database or CMS, not in static HTML files. This prevents dates from drifting.

⏱ 3–4 hours (audit + updates)

Assess Member Directory State
Essential
▼

The problem: The member directory is login-gated (correct), but its current state is unknown. How many members are actually in the system? Does the search work? Can members edit their own profiles? Is the data complete?

Why it matters: The member list is the core value proposition of the site. If it's broken or out of date, the whole membership program is undermined.

What to test

  • Total member count (check the database or admin panel)
  • Search functionality — can you find a member by name or institution?
  • Profile editing — can a member log in and update their info?
  • Data completeness — are all members listed? Do profiles have required fields filled?
  • Lapsed members — are expired memberships marked correctly?

How to do it

Create a test account if needed. Log in and browse the member list. Try searching for your name. Try editing your profile. Verify the member count matches what the treasurer expects.

Document your findings

Write down what works and what doesn't. Share this with the officers so they know the state of the system before your changes.

⏱ 1–2 hours (testing)

Verify Newsletter PDF Archive
Nice to Have
▼

The task: All 44 newsletter PDFs are hosted on the current server. If the site ever migrates to new hosting, these files must be moved or re-linked. First, verify all the links still work.

Why it matters: A broken newsletter archive kills credibility. Scholars expect to be able to access 30 years of organizational history.

What to check

  • Are all 44 PDF links returning 200 OK (not 404)?
  • What's the total file size of the archive? (Will this fit on new hosting?)
  • Where on the server are the PDFs stored? (Note the path for migration planning.)
  • Are any PDFs corrupted or missing from the sequence?

How to do it

Visit the newsletter archive page. Check a few PDFs from different years — do they download correctly? Keep a spreadsheet of the file sizes and paths if they vary.

Migration planning

If the site moves to a new platform, you'll need to either download all PDFs and re-upload them, or set up URL redirects so old links don't break.

⏱ 30 minutes (verification)

2. Short-Term Easy Improvements (1–2 weeks)

Low-effort wins that improve usability and reduce ongoing maintenance burden. These can run in parallel with fixes.

Build Member Management Dashboard
Essential
▼

The problem: Officers need to answer basic questions — How many active members? Who is lapsed? When do memberships expire? — but right now they have to query the database directly or use a spreadsheet that constantly drifts out of sync.

What you'll build: A simple admin dashboard showing active members, lapsed members, members expiring soon, and recent new joins. One-click CSV export for treasurer and board reports.

Dashboard features

  • Total active member count
  • Lapsed members (expired > 30 days)
  • Members expiring in next 60 days
  • New members this month
  • Search by name, email, or institution
  • CSV export for reports and mailing lists

Platform fit

WordPress + MemberPress: Built-in. Configure and go. 1–2 hours.

Outseta: Built-in CRM view. 30 minutes.

Custom PHP: Write a SQL query and render as HTML table with PDF/CSV export. 4–8 hours.

⏱ 30 min–8 hours depending on platform

Officer Directory Self-Management Form
Essential
▼

The problem: Currently, updating the officer directory requires editing files or database records directly. When someone becomes president, someone has to remember to update the contact page. Inevitably, something gets missed — like what happened with the 404 contact page.

The fix: Create a form where each officer can update their own entry. The contact page pulls from the database and renders automatically. It's never stale because it's data-driven, not a static file.

What to build

A simple admin form, one per officer role:

  • Role title (President, Treasurer, etc.) — locked in, not editable
  • Name
  • Institution
  • Email address
  • Profile/ORCID URL (optional)
  • Bio (optional)

How it prevents breakage

When the treasurer changes, the outgoing treasurer (or the webmaster) updates one form. The contact page reflects it immediately. No files to edit, no static HTML to update.

Implementation

WordPress: ACF Options Page with a repeater field. Custom PHP: HTML form + UPDATE query. Either takes 2–3 hours.

⏱ 2–3 hours

Set Up Role-Based Admin Access
Nice to Have
▼

The problem: Currently there's no middle ground — you either have full server access (webmaster only) or no access. The newsletter editor can't publish without the webmaster. The treasurer can't view payment records.

The solution: Define specific roles: Newsletter Editor, Blog Editor, Treasurer (view records), Officer (edit own info). Each role has exactly the permissions it needs.

Roles to create

  • Newsletter Editor: Upload PDFs, publish new issues, send member emails
  • Blog Editor: Create and publish blog posts
  • Session Organizer: Edit conference session listings
  • Treasurer: View and export member payment records (read-only)
  • Officer: Edit their own directory entry

⏱ 2–4 hours (WordPress) or built-in (Outseta/Wild Apricot)

Newsletter Upload & Publish Interface
Essential
▼

The problem: Publishing a newsletter currently requires FTP access, knowledge of the exact server directory path, and manually editing the page to add the new entry. The newsletter editor (a volunteer) is blocked from publishing independently. The webmaster must do it, creating a bottleneck.

The fix: A simple form where the editor uploads the PDF, enters Season/Year/Issue#, and clicks Publish. Everything happens automatically — upload, archive update, member email announcement.

What the form does

  1. Editor selects PDF from their computer
  2. Enters: Season (Spring/Fall), Year, Issue number
  3. Clicks Publish
  4. PDF uploads to server automatically
  5. Newsletter archive page updates automatically
  6. Email announcement sent to all members

Who can use it

Only the newsletter editor and webmaster. (Use role-based access control.)

Implementation options

WordPress: Custom post type for newsletters, file upload via ACF, automatic email via MailPoet. 4–6 hours.

Wild Apricot: Built-in document library + email tool. 1 hour to set up.

Custom PHP: Upload handler + database INSERT + email function. 4–6 hours.

⏱ 1–6 hours depending on platform

Integrate Member Email List with Membership DB
Essential
▼

The problem: The member email list (likely a separate Mailman or Listserv) is not synced with the website's membership database. When someone joins, they're added to the list manually. When they lapse, they stay on the list. Two systems, zero coordination.

The fix: Active members automatically receive announcements. Lapsed members stop receiving them. One source of truth: the membership database.

How it works

When someone's membership status changes in the database, they're automatically added or removed from the email list. No manual sync needed. No lapsed members getting emails.

Implementation options

Zapier: Automation watches for membership status changes and updates the email list. 1–2 hours to set up.

Outseta/Wild Apricot: Built-in. Configure in dashboard. 30 minutes.

Custom PHP: Add a database trigger that fires when membership status changes. 2–3 hours.

⏱ 30 min–3 hours depending on platform

3. Long-Term Labor-Intensive Improvements (2–6 months)

These transform the site from a maintenance burden into a field resource. They require editorial direction and sustained volunteer effort, but they address the underlying problem: declining attendance and interest.

Create Living Bibliography of Magic Studies
Nice to Have Field Builder
▼

The problem: Magic studies publications are scattered across a dozen disciplines (history, religious studies, anthropology, classics, literature). There's no single searchable source. Scholars constantly miss relevant work.

Why build it: Makes the Societas a destination scholars visit regularly to check new publications. Searchable by period, region, subject. Non-members can access it — a recruitment tool. RSS feed for scholars to subscribe.

What to build

A searchable database of new publications (books, articles, dissertations) in magic studies. Fields: author, title, year, publication type, period, region, subject tags, annotation. Members can submit citations. Monthly RSS feed.

Implementation

WordPress custom post type + FacetWP (search/filter), or Airtable with embedded interface. A volunteer editor curates and adds ~10 publications/month.

⏱ 1–2 days build + 5–10 hours/month editorial

Dissertation Registry & Grad Student Hub
Nice to Have Membership Growth
▼

Why it matters: Graduate students are the future of conference attendance. The site has no hook into this community. A searchable registry of dissertations (in progress and completed) creates that connection.

The hook: A grad student working on Paracelsus finds two others working on similar topics. They connect, join the Societas, attend Kalamazoo. This compounds into larger conference attendance.

What to build

Searchable registry of dissertations with: author, institution, advisor, title, status (in progress/completed), abstract, tags (period, region, subject), "open to correspondence" checkbox.

⏱ 1–2 days build (shares code with bibliography) + minimal ongoing

Field-Wide Conference Calendar & CFP Digest
Nice to Have Engagement Driver
▼

The problem: Magic studies scholars present at 50+ different conferences annually. There's no single place to see all the CFPs and deadlines. Scholars miss submissions because they weren't on the right mailing list.

The win: A calendar scholars bookmark and check monthly. Members can submit CFPs. Monthly digest: "10 deadlines this month." People visit the site regularly.

What to build

Calendar of conferences, CFPs, and deadlines across the field. Searchable, filterable by type. Members can submit new events. Monthly email digest sent to all members.

⏱ 1 day build + 5 hours/month curation

Rich Member Profiles with ORCID Integration
Nice to Have Collaboration Tool
▼

Currently: Member directory is a phone book — names and emails. Potential: A discovery tool. Search for peer reviewers by specialty, find scholars to organize sessions with, identify potential committee members.

How: Enrich profiles with research interests (tagged), current projects, recent publications (auto-pulled from ORCID), languages, availability for peer review/committees/media.

New profile fields

  • Research interests (tagged by period, region, subject)
  • Current projects
  • Recent publications (pulled from ORCID API)
  • Languages of research
  • Available for peer review / committees / conference org / media consultation

⏱ 1 day build + setup

Ars Magica Blog — Editorial Program
Nice to Have Visibility + Community
▼

Currently: One blog post from 2021. A dormant blog signals a dormant organization. Potential: 6–8 posts per year = shareable content, SEO boost, reason for scholars to follow the Societas.

Content types: Research previews, source spotlights, pedagogical posts, conference reports, new book forums, dissertation spotlights. Dissertation spotlights especially valuable for recruiting grad students.

Editorial structure

Two editors rotate solicitation duties. Post topics planned monthly. ~3–4 hours per post (solicit, edit, publish). WordPress infrastructure is zero setup.

⏱ 15–20 hours/month editorial effort

Open-Access Working Papers (via Zenodo)
Nice to Have Field Infrastructure
▼

The problem: Scholars have conference papers, grant reports, and draft chapters that are substantial but not journal-ready. They sit on hard drives, uncited.

The solution: Papers hosted with Societas branding get cited. Those citations carry the organization's URL. Positions the Societas as field infrastructure. Best part: free DOI via CERN's Zenodo.

How it works

Create a Zenodo community (free, run by CERN). Members upload PDFs directly to Zenodo, select the Societas community. Papers get permanent DOIs and are citable. Societas URL appears in bibliographies forever.

⏱ 1 hour setup + minimal curation

Virtual Event Infrastructure
Nice to Have
▼

Why: In-person attendance is down across academia. Travel costs, visa issues, accessibility. Virtual events extend reach to members who can't get to Kalamazoo.

What to offer: Annual recorded lecture, pre-Kalamazoo virtual roundtable (ask questions about sessions), quarterly virtual working groups by research area, grad student mentorship cohorts.

Event types

  • Annual invited lecture (recorded, posted on YouTube)
  • Pre-Kalamazoo roundtable (scholars who can't travel can ask questions)
  • Quarterly working groups by research area
  • Grad student mentorship cohorts (semester-long pairing)

⏱ ~5–10 hours/month organizational

Implementation Roadmap

Phase 1 (Weeks 1–4): Restore contact page, stabilize PayPal, update stale content, build member dashboard and officer form, set up role-based access. Goal: Site stability and basic usability.

Phase 2 (Weeks 5–12): Newsletter upload interface, email list integration, blog editorial program. Goal: Reduce webmaster burden, maintain active content flow.

Phase 3 (Months 4–6): Living bibliography, dissertation registry, conference calendar, rich member profiles. Goal: Make the site a field resource, drive attendance and engagement.

Phase 4 (Ongoing): Working papers, expert directory, virtual events. Goal: Long-term visibility and community building.
