Automation & Modern Tech Vision

How React, APIs, and intelligent automation will transform Societas Magica from a manual admin burden into a self-service scholarly platform.

⚡The Problem: Manual & Brittle

The current site (14-year-old custom PHP) works, but it's entirely manual:

🔁 Renewal Reminders

Current: Officer manually checks who's overdue, sends individual emails. 351 members are "older than 2 years."

Problem: Falls through the cracks. No one knows whose dues are expiring until they're delinquent.

📝 Officer Profile Updates

Current: Officer emails you to update contact info. You log into admin panel and manually update.

Problem: You're the bottleneck. Takes 30 min per email.

📰 Newsletter Publishing

Current: Editor emails you PDF + metadata. You fill in season/year/issue/author manually in admin panel.

Problem: Slow, error-prone. Publishing takes a day instead of 10 minutes.

📊 Officer Dashboard

Current: Treasurer asks you "How many paid this month?" You run a manual query.

Problem: Officers are blind to data. You're doing their job.

🔧Solution 1: Renewal Reminders (Email Automation)

❌ Current (Manual)

  1. Officer manually reviews dues tracker
  2. Creates mental list of overdue members
  3. Drafts email to each member
  4. Sends individually (or forgets)
  5. Result: 20-30% delinquency rate

Time: 2 hours/month

✅ Modern (Automated)

  1. Cron job runs daily at midnight
  2. Queries: "Whose membership expires in 60 days?"
  3. Sends templated email automatically
  4. Repeats for renewal date and 30-days-overdue
  5. Result: 50%+ reduction in late payments

Time: 5 mins setup, 0 mins ongoing

💌 Sample Automated Emails (sent by system) --- Subject: Your Societas Magica Membership Renews in 60 Days Dear [Member Name], Your Societas Magica membership will expire on [DATE]. Renew now and keep your access to: • Exclusive newsletter archive (44 issues, 1995–2026) • Member directory • Conference calendar • 20% discount on Magic in History books → [Renew Your Membership] --- Subject: Your Membership Expires TODAY Dear [Member Name], Your membership expires today. Without renewal, you'll lose access to: • Member-only content • Newsletter archive • Officer contact directory → [Renew Now] (takes 2 minutes) Your support keeps Societas Magica running. ---

⚙️ How It Works (Tech Side)

  • Cron Job: Scheduled task runs at 2 AM daily
  • Query: `SELECT * FROM members WHERE expiry_date = CURDATE() + 60 DAYS`
  • Template: Use existing email system (PHP mail or SMTP)
  • Logging: Log each email sent (audit trail)
  • Opt-out: Members can disable reminders in preferences

Implementation: ~40 hours (mostly template design & testing)

👤Solution 2: Officer Self-Service (API + React Form)

❌ Current (You're the Gatekeeper)

  1. Officer emails you: "I moved, update my address"
  2. You log into admin panel
  3. Find officer's record
  4. Manually edit name, phone, email, bio
  5. Save
  6. Reply to officer: "Done"

Time per request: 10-15 minutes

Friction: Officer has to wait for you

✅ Modern (Self-Service Form)

  1. Officer clicks "Edit My Profile" on member page
  2. Form loads with their current info
  3. They update fields (name, phone, email, bio)
  4. They click "Save"
  5. Changes auto-save to database
  6. Auto-notifies you (optional approval workflow)

Time per request: 2 minutes (for officer)

Friction: Zero waiting

  • On save, React sends PATCH request to API: `/api/officers/me`

  • Public page refreshes automatically (no cache needed)

⚙️ Why React + API is Better

  • Instant Feedback: Form validates as you type (red underline if email is invalid)
  • No Page Reload: Click save, data saves, you see confirmation in 100ms
  • Real-Time Sync: Changes appear on public profile page immediately
  • Offline-Capable: Form can queue changes if offline, syncs when internet returns
  • Mobile-Friendly: Touch-optimized form works perfectly on phones
  • Accessibility: Screen reader support built-in (ARIA labels)

Implementation: ~30 hours (React form + API endpoint)

📰Solution 3: Newsletter Self-Publishing (React Upload + Auto-Metadata)

❌ Current (You're Required)

Editor emails you: "Here's the Spring 2026 newsletter. Frater Archer. 'Making of the Lemegeton.'"

  1. You log into admin panel
  2. Click Newsletters → Upload
  3. Select Season: "Spring"
  4. Select Year: "2026"
  5. Type Issue No: "44"
  6. Type Author: "Frater Archer"
  7. Type Title: "Making of the Lemegeton"
  8. Upload PDF
  9. Click Save

Time: 10 minutes per newsletter

Error Rate: ~15% (wrong issue # is common)

✅ Modern (Auto-Numbered, Drag-Drop)

Editor clicks "Publish Newsletter" on member page:

  1. Form appears (pre-filled with "Spring 2026")
  2. Issue # auto-calculated: "Issue 44"
  3. Drag-drop PDF into form
  4. Type Author: "Frater Archer"
  5. Type Title: "Making of the Lemegeton"
  6. Click "Publish"

Time: 3 minutes per newsletter

Error Rate: 0% (auto-numbering)

💡Key Insight: You Don't Need a "Redesign"

You don't need to redesign the entire site at once. Modern approach is surgical modernization:

  1. Keep the database. It works. Don't migrate.
  2. Build an API layer. Let the database speak JSON.
  3. Add React components one at a time. Officer form first. Newsletter upload second. Dashboard third.
  4. Leave old pages alone. Home page, Publications, Blog—stay on PHP. They work.
  5. Gradually replace. Over 6 months, 60% of the site is React. After 12 months, retire the PHP.

Benefit: Low risk. If something breaks, roll back the one component. The rest of the site keeps working.

🛠️ Recommended Tech Stack

  • Backend: Node.js (Express) + existing MySQL database
  • API: REST (or GraphQL if doing Dissertation Registry later)
  • Frontend: React 18+ (component library like Material UI or Chakra)
  • Authentication: JWT tokens (decouples frontend from PHP sessions)
  • Hosting: Same shared hosting or move to cloud ($50-100/month for better performance)
  • CI/CD: GitHub Actions (auto-deploy on git push)
