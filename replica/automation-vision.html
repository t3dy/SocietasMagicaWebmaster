Automation & Modern Tech Vision

How React, APIs, and intelligent automation will transform Societas Magica from a manual admin burden into a self-service scholarly platform — with real mockups of what each improvement looks like.

⚡ The Problem: Manual & Brittle

The current site works, but it's entirely manual. Every task flows through you or Paul:

🔁 Renewal Reminders

351 members are more than 2 years lapsed. No automated system has ever reminded them to renew. It requires manual lookup and individual emails.

📝 Officer Profiles

Officer emails you a change. You log into admin, find the record, edit it manually, reply "done." 15 minutes per change that should take 2.

📰 Newsletter Publishing

Editor sends you a PDF by email. You fill in season, year, issue number, author, title by hand. One wrong number breaks the archive sequence.

📊 Financial Visibility

Treasurer asks "how many paid this month?" You run a database query. Officers are blind to membership health without your intervention.

📧 Solution 1: Automated Renewal Reminders

❌ Current — manual
  1. Officer manually reviews dues tracker
  2. Builds mental list of overdue members
  3. Drafts individual emails
  4. Sends them one by one — or forgets
Time: ~2 hours/month  |  Outcome: 20–30% delinquency
✅ Modern — automated
  1. Cron job runs nightly at 2 AM
  2. Queries: who expires in 60 / 30 / 0 days?
  3. Sends templated email to each group
  4. Logs every email sent for audit trail
Time: 0 mins ongoing  |  Outcome: 50%+ fewer lapses

How it works

  • Cron job runs at 2 AM daily — queries the existing MySQL members table
  • Three triggers: 60-day warning, 30-day warning, expiry-day notice
  • PHP mailer or SendGrid handles delivery with SPF/DKIM so it lands in inboxes, not spam
  • Audit log: every email stored in a email_log table — who got what and when
  • Opt-out: one-click unsubscribe link in every email (legal requirement)
  • Effort: ~40 hours — most of that is testing the email templates

👤 Solution 2: Officer Self-Service Profile

❌ Current — you're the gatekeeper
  1. Officer emails: "I moved, new phone is…"
  2. You log into the admin control panel
  3. Find their record in the member table
  4. Manually edit the fields
  5. Reply confirming it's done
Time: 10–15 min per change  |  Friction: officer waits for you
✅ Modern — self-service
  1. Officer clicks "Edit My Profile" on their member page
  2. Form loads pre-filled with their current data
  3. They update what's changed and hit Save
  4. Database updates in <100ms
  5. Public officer listing refreshes automatically
Time: 2 min for officer  |  Friction: none

How it works

  • React form pre-populates with a GET request to /api/officers/me
  • Real-time validation as you type — red border + error message if email is malformed
  • On Save, sends a PATCH to /api/officers/:id — database updates in under 100ms
  • Public officer listing is server-rendered from the same table — no cache to clear
  • Optional: changes go into a pending approval queue for webmaster sign-off before going live
  • Effort: ~30 hours — React form + one API endpoint

📰 Solution 3: Newsletter Self-Publishing

❌ Current — you're required
  1. Editor emails you: PDF + metadata as freeform text
  2. You log into admin, click Newsletters → Upload
  3. Fill in Season, Year, Issue #, Author, Title by hand
  4. Upload the file, click Save
  5. Hope you typed Issue #44 and not #43
Time: 10–15 min  |  Error rate: ~15% (wrong issue # common)
✅ Modern — editor publishes directly
  1. Editor clicks "Publish Newsletter" on their member page
  2. Season + Year pre-filled; Issue # auto-calculated as #45
  3. Drag PDF into the drop zone
  4. Fill in Title + Author, click Publish
  5. Archive updates; members get a notification email
Time: 3 min  |  Error rate: 0% (auto-numbered)

How it works

  • Issue # auto-increments: API queries MAX(issue_no) + 1 from the newsletters table — no human counting
  • Drag-drop upload: File API in the browser handles it; a progress bar appears for large PDFs
  • PDF validation: File type and size checked before upload starts
  • Member notification: If checked, queues a batch email to all active members using the existing mailer
  • Role-gated: Only users with the newsletter_editor role see this page
  • Effort: ~50 hours — form + file upload API + email queue integration

How it works

  • All data from the existing MySQL database — no migration, no new schema
  • React renders client-side: sorting and filtering columns is instant, no server call needed
  • Revenue bars: CSS-only chart — no heavy charting library required for this level of display
  • "Send Reminder" button calls POST /api/reminders/send/:memberId and queues the email
  • "Export CSV" calls GET /api/members/export.csv — browser downloads the file directly
  • Effort: ~60 hours — API endpoints + React dashboard components

⚛️ Why React + Modern Stack?

⚡ No Page Reloads

Click Save — data saves in the background. No white flash, no waiting. Confirmation appears in 100ms.

Better UX

✅ Inline Validation

Email field turns red the moment the format is wrong — before you even try to submit. No more "please try again."

Fewer Errors

📱 Mobile-First

Officers updating profiles from a phone at Kalamazoo works as well as at a desktop. Touch targets are large, forms reflow to one column.

Accessibility

🔄 Real-Time Data

Dashboard numbers refresh every 60 seconds without a page reload. Treasurer always sees current membership counts.

Live Updates

🔗 API-First

Everything talks through APIs. Adding ORCID, Zotero, Google Calendar, or a Stripe webhook later is a new endpoint — not a site rewrite.

Extensible

🧩 Component Reuse

The member profile form, the officer form, and the newsletter form all share the same form components. Build once, use everywhere.

🏗️ Implementation Roadmap

You don't rewrite the whole site. You replace pieces one at a time — old PHP stays running while each React component goes live beside it.

Phase 1 · Now

Stabilize

Bug fixes, backups, stale content updates, SSL check. No new features. Gets the foundation solid.

Phase 2a · 8 wks

API Layer + Reminders

Build REST API over existing MySQL. Add renewal reminder cron job. Email delivery fixed as part of this.

Phase 2b · 12 wks

Self-Service Forms

Officer profile form. Newsletter publish form. Role-based access so editors don't need webmaster.

Phase 2c · 6 wks

Treasurer Dashboard

Real-time membership health view. Bulk reminder send. CSV export. Officers stop asking you for data.

Phase 3 · 16 wks

Scholarly Features

Bibliography, dissertation registry, ORCID integration, rich member profiles. Site becomes a field resource.

Total: ~6 months at half-time, or ~3 months with a contractor. Cost range: $15k–$30k depending on who builds it.

The key insight: this isn't a redesign. It's surgical modernization — keep the database, keep the PHP pages that work, and replace the manual bottlenecks one component at a time. If anything breaks, roll back that component. The rest of the site keeps running.
