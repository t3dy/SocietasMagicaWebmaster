This guide covers everything a new webmaster needs to take over, stabilize, and modernize the Societas Magica website.

What this guide is

Societas Magica is an academic society for scholars of the history of magic, founded in 1994. Its website runs on a custom PHP application built by volunteers — functional but aging. This field guide maps every task a new webmaster faces: recovering access, auditing the codebase, repairing broken features, and choosing a path to bring the site into 2026.

Each section explains the concept, the tools, the steps, and links to the best external learning resources for that technology.

1 Access Recovery

Before you can fix anything, you need the keys. This is the most urgent task and should happen before the outgoing webmaster goes dark.

What you need to collect

  • Hosting credentials — cPanel login, SSH key, or FTP username/password. This is how you reach the server.
  • Domain registrar login — whoever holds societasmagica.org controls DNS. If this lapses, the site disappears.
  • Database credentials — MySQL username, password, database name. Usually in a config file on the server (e.g., config.php or .env).
  • Source code — Is there a Git repository? Or is the code only on the server? You need a copy under version control.
  • PayPal account — API keys or at minimum the email address linked to the PayPal business account used for dues.
  • Email/listserv credentials — Does the org use a mailing list? Who administers it?

SSH — Secure Shell

SSH lets you log into the server as if you were sitting at its terminal. Most web hosts (DreamHost, SiteGround, etc.) provide SSH access. Once connected, you can read files, export the database, and inspect the PHP code.

# Connect to a server
ssh youruser@societasmagica.org

# Export the full database to a file
mysqldump -u dbuser -p dbname > backup.sql

# Pull all site files to your local machine
scp -r youruser@societasmagica.org:/path/to/site ./site-backup

Learn more

  • DigitalOcean: How To Use SSH to Connect to a Remote Server
  • GitHub Docs: Connecting to GitHub with SSH
  • SSH Academy: SSH Command Reference

DNS — Domain Name System

DNS is the phone book that maps societasmagica.org to the IP address of the server. The domain registrar (e.g., GoDaddy, Namecheap, Network Solutions) controls this. Losing access to the registrar is an emergency — it means you can't point the domain at a new server or renew it.

Learn more

  • Cloudflare: What is DNS?
  • Namecheap: DNS Guru Guides
  • Google: Introduction to DNS

Git — Version Control

If the site code isn't in a Git repository, your first act should be creating one. Git tracks every change to every file, lets you roll back mistakes, and makes collaboration safe.

# Initialize a repo in the site folder
git init

# Add all files and make the first commit
git add .
git commit -m "Initial commit: site as inherited"

# Push to GitHub
git remote add origin https://github.com/YourOrg/sm-site.git
git push -u origin main

2 Audit & Triage

Once you have access, read the codebase and database before touching anything. Understand what you have before you change it.

Reading a PHP application

The Societas Magica site is a custom PHP application. PHP is a server-side scripting language that generates HTML dynamically. In a custom app (no framework), the codebase typically looks like:

  • index.php — the entry point, handles routing
  • config.php or .env — database credentials, site settings
  • themes/ — HTML templates
  • users.php, members.php — feature modules
  • sql/ — database schema or migrations

Clues already visible on the site: themes/default/images/ path, ?page=TravelBursary.html query parameter pattern, and routes like /users/run_once — all signatures of hand-rolled PHP, not a major CMS.

Inspecting a MySQL database

The member list, newsletter posts, and user accounts all live in a database. Use a GUI tool to explore it safely.

# List all tables
SHOW TABLES;

# See the structure of the members table
DESCRIBE members;

# Count active members
SELECT COUNT(*) FROM members WHERE active = 1;

Tools for database inspection

  • phpMyAdmin — web-based MySQL GUI, often pre-installed on shared hosting
  • TablePlus — modern Mac/Windows desktop GUI for databases
  • DBeaver — free, cross-platform database tool

Learn PHP

  • PHP.net: Getting Started (official tutorial)
  • PHP The Right Way — modern PHP best practices
  • Laracasts: PHP For Beginners

Checklist: First-week audit

  • List every route/URL and test each one — note 404s and broken pages
  • Find every page with a stale "Updated:" timestamp (several are from 2012)
  • Map the database schema: tables, columns, relationships
  • Count members in the DB vs. what officers believe is active
  • Identify the PHP version on the server (php --version via SSH)
  • Check SSL certificate status (is HTTPS valid and auto-renewing?)
  • Find where PayPal sends callbacks — the IPN or webhook endpoint
  • Identify all hardcoded email addresses in the code

4 Member Directory

The member list is the most valuable feature of the site — it's the main reason scholars pay dues. It's currently login-gated (correct) but its internal state is unknown. This section explains the concept and the best 2026 options.

How a member directory works

A member directory is a login-protected database view: members log in, see each other's profiles (name, institution, research interests, email), and can update their own entry. The backend stores records in a database table; the frontend renders them as HTML with optional search and filter.

What the current site likely has

  • A members or users table in MySQL
  • A PHP page that queries that table and renders the list
  • A session check at the top to verify the user is logged in
  • No self-service profile editing (typical of early-2000s hand-rolled systems)

Option A — Repair the existing system

If the PHP member list is mostly working, repair and document it. Add:

  • A search/filter field (JavaScript on the rendered HTML table)
  • A self-service profile edit form (new PHP page with a UPDATE query)
  • Pagination if the list is long

Option B — WordPress + MemberPress

MemberPress is the most established WordPress plugin for membership management. It handles registration, login, dues, renewal reminders, and a member directory out of the box.

  • MemberPress: Member Management features
  • MemberPress: Getting Started Guide
  • ProfilePress: Building a WordPress Member Directory

Option C — Wild Apricot

Wild Apricot is a hosted platform purpose-built for associations, academic societies, and nonprofits. It includes member database, dues billing, event registration, email blasts, and a website builder — all in one subscription with no custom code required.

  • Wild Apricot: Membership Management overview
  • Wild Apricot: What is a Membership Database?
  • Wild Apricot: Pricing (starts ~$60/mo)

Option D — Outseta

Outseta is a modern all-in-one platform combining authentication, billing (Stripe-backed), CRM, and member profiles. Unlike Wild Apricot it integrates cleanly with a custom or static frontend, making it the best choice if you want design control.

  • Outseta: Membership features
  • Outseta: Documentation

5 Payments & Dues

The site uses PayPal for membership dues. PayPal was recently broken and then fixed. This section explains how payment integration works and what a modern replacement looks like.

How the current PayPal flow works

PayPal's classic integration uses IPN (Instant Payment Notification): when someone pays, PayPal sends a POST request to a URL on your server (e.g., /paypal/callback.php). That script verifies the payment and updates the member's status in the database. If that URL breaks or the script has a bug, payments succeed at PayPal but don't activate membership — which is exactly the kind of failure that was reported.

// Simplified IPN handler concept (PHP)
$payment_status = $_POST['payment_status'];
$payer_email    = $_POST['payer_email'];

if ($payment_status === 'Completed') {
    // Find member by email, set active = 1, update expiry date
    $db->query("UPDATE members SET active=1, expires=DATE_ADD(NOW(), INTERVAL 1 YEAR)
                WHERE email = ?", [$payer_email]);
}

PayPal resources

  • PayPal: IPN (Instant Payment Notification) docs
  • PayPal: Modern Checkout integration

Why Stripe is a better choice in 2026

Stripe has become the standard for online payments. Its API is cleaner than PayPal's, its webhook system is more reliable than IPN, it handles recurring subscriptions natively (important for annual dues), and its dashboard is far more transparent for non-technical officers who need to see who has paid.

// Stripe webhook handler concept (PHP)
$payload = file_get_contents('php://input');
$event   = \Stripe\Webhook::constructEvent($payload, $_SERVER['HTTP_STRIPE_SIGNATURE'], $secret);

if ($event->type === 'checkout.session.completed') {
    $email = $event->data->object->customer_details->email;
    // Activate membership for $email
}

Stripe resources

  • Stripe: Checkout — quickest way to accept payments
  • Stripe: Webhooks — how to respond to payment events
  • Stripe: Subscriptions — recurring dues
  • Smashing Magazine: Stripe Payments Integration walkthrough

Subscription / renewal logic

Annual dues need renewal reminders. A modern approach:

  • Stripe Billing — handles recurring charges, sends renewal receipts, handles failed payment retries automatically
  • Email reminders — 30/7/1 day before expiry via a cron job or Stripe's built-in dunning emails
  • Grace period — typically 30 days of access after expiry before locking the member out

6 Migration Paths

The custom PHP codebase is the biggest long-term risk. It depends on one person's knowledge and can break silently on a PHP version upgrade. These are the three realistic paths forward.

Path A — Stabilize the Current Stack

What: Keep the custom PHP. Put it in Git. Document it. Move to a VPS you control. Fix broken pages.

Effort: Low (2–4 weeks)

Cost: ~$10–20/month hosting (DigitalOcean, Linode)

Risk: Still fragile. One PHP version upgrade can break undocumented code. No volunteer can easily take over from you.

Best if: The board wants minimal disruption and the site is mostly working.

VPS hosting guides

  • DigitalOcean: LAMP Stack on Ubuntu (PHP hosting tutorial)
  • Linode: LAMP Stack setup guide

Path B — Migrate to WordPress

What: Move content to WordPress. Use MemberPress or ProfilePress for member management. Stripe for payments. Export the member database and import it.

Effort: Medium (4–8 weeks)

Cost: ~$15/month hosting + ~$30/month for plugins

Risk: WordPress requires ongoing plugin/security updates. But it's maintainable by any tech volunteer.

Best if: The org wants long-term sustainability without a dedicated developer.

WordPress migration resources

  • WordPress.org: Official documentation hub
  • Kinsta: How to Migrate to WordPress
  • MemberPress: Building a WordPress membership site
  • WPBeginner — beginner-friendly WordPress tutorials

Path C — Static Site + Managed Services

What: Rebuild the public site as a static HTML/CSS site (or Astro/Hugo) hosted on Netlify or GitHub Pages (free). Delegate auth, billing, and member directory to Outseta or Memberstack. Stripe for payments.

Effort: High (8–16 weeks) — but results in the most modern, durable architecture.

Cost: $0 hosting + $49–79/month for Outseta/Memberstack

Risk: Requires frontend skills and a larger initial investment of time.

Best if: The org is willing to invest once for a system that runs itself for years.

Static site & Jamstack resources

  • Astro — modern static site generator, excellent for content sites
  • Hugo: Quick Start — fastest static site generator
  • Netlify: Get Started (free hosting for static sites)
  • Jamstack.org: What is Jamstack?

Database migration: exporting and importing member records

Whichever path you choose, the member database must be migrated carefully. No member should lose their account or be asked to re-register.

# 1. Export from the old MySQL database
mysqldump -u olduser -p olddb members > members_export.sql

# 2. Inspect the data — check field names, email formats, active flags
# 3. Map old fields to new schema (name, email, institution, active, expires)
# 4. Import into new system — most platforms accept CSV imports

Interview prep summary

The three things to know cold going into the Societas Magica webmaster interview:

  1. Access first. The site is only as recoverable as the credentials you can collect from the outgoing webmaster. Ask about hosting, domain, database, PayPal, and source code — in that order.
  2. The member list is the product. Everything else is content. The reason scholars pay dues is to appear in and access the member directory. Getting that working and self-serve is the highest-value improvement.
  3. Path B (WordPress + MemberPress) is the pragmatic choice. It's the option a future volunteer can take over without knowing PHP, which is what a small academic society needs.
